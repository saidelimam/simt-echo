## Findings

### W3-05 — Grounding: box-only + SAM 3.1 (BLOCK)

- **B1 (BLOCK)** Mask decoding is dead code: `ground.ts` hand-strips the
  mask payload and calls `decodeMaskToSVGPath` with frame dims as raster
  dims; every failure is swallowed, so `maskSvgPath` can never be produced
  and every grounded candidate silently degrades to box-only. `parseSam`
  also drops which object a mask belongs to.
- **B2 (BLOCK)** Malformed SAM output (float/inverted/zero-area boxes,
  confidence outside 0–1) passes `parseSam` and then fails
  `JobResultSchema.parse` outside any try/catch — one bad record errors
  the whole job instead of degrading. Acceptance says never crashing.
- **B3 (BLOCK)** No test drives a fixture SAM response through `runGround`:
  no `AI_GROUNDED` candidate, no mask, no Meta failure, no degenerate SAM.
- **M1 (MAJOR)** Fallback-a (image grounding) deviates from §10: no-clip
  and missing-clip checkpoints never attempt it, and when it runs it keeps
  real trackability/visibleFromM instead of the mandated nulls.
- **M2 (MAJOR)** Hero-null candidates fall back to the scout's 0–1000-grid
  box while `frameW/H` are SAM pixels — mixed coordinate systems.
- **M3 (MAJOR)** Box-only candidates are emitted in scout order, not the
  §6.6 rank order the SAM path uses.
- Deferred by plan: pipeline still discards ground output from the public
  result (W3-06 owns assemble); per-candidate Workflow steps likewise.
- Verified good: §6.6 formulas verbatim (score, ranking, visibleFromM,
  heroIndex, spark→pixels), SAM request shape/§7.3 error split, box-only
  null discipline, key only in the Authorization header.

### W4-01 — Trials: baseline, drift, CSV export (BLOCK)

- **B1 (BLOCK)** No writer exists: no code creates, logs, or exports a
  trial. Arrived is unchanged (its KDoc assigns the write to this slice),
  there is no marker logging, no baseline handling in Navigate, and no
  Settings export. The §11 protocol cannot be run in the app.
- **B2 (BLOCK)** §11 fields missing from the trial shape: mistaken landmark
  confirmations, lighting, holding style / notes — the CSV is incomplete
  by construction and could only be completed by hand-editing.
- **M1 (MAJOR)** Storage is `trials/<id>/trial.json`; spec §5.3/§10 says
  `trials/<trialId>.json`.
- **M2 (MAJOR)** Export concatenates two tables (runs + markers) into one
  file; a standard CSV reader ingests the second header as data.
- **M3 (MAJOR)** `mode` and `baselineMode` are independent fields that can
  contradict each other in exported rows.
- **M4 (MAJOR)** Same-ID saves silently overwrite; one corrupt trial file
  throws out of `list()`/`exportCsv()` and blocks all export.
- **M5 (MAJOR)** Tests assert substrings, not exact CSV; protocol fixture
  is 2+2 runs, not 5+5.
- Verified good: drift sign (`estimated − expected`, tested both ways),
  RFC-4180 escaping core, locale-independent numbers, epoch timestamps,
  CSV carries only protocol data.

### W4-02 — Calibration: step-K + EchoConfig (BLOCK)

- **B1 (BLOCK)** Persisted config is never loaded: `AppGraph` exposes no
  config repository, `RecordScreen` builds `CaptureSession` with the
  hard-coded default, and `BuiltInPdrMotionSource` does not implement
  `StepCalibratable`, so the `as?` push silently no-ops on Android. The
  Navigator likewise always gets default config. Calibrated K changes
  nothing at runtime.
- **B2 (BLOCK)** The drift test is arithmetic (`25 · (10/12.5) = 20`)
  bypassing the engine; no fixture proves `PdrEngine` distance error
  shrinks with calibrated K (and the per-step clamp makes the effect
  non-linear, which only an engine test can size).
- **M1 (MAJOR)** No bounds on K: zero/negative/huge/NaN all persistable.
- **M2 (MAJOR)** `EchoConfig.baselineMode` is written by Settings and read
  by no one.
- **M3 (MAJOR)** Settings ViewModel uses `remember { }` — the pattern
  review 0001 removed in favour of back-stack `viewModel()`.
- Verified good: calibration direction `K·true/measured`, no double
  application in capture, corrupt-file → defaults, frozen EchoConfig
  defaults untouched.

into the video parser, parser's mask→SVG helper, raster dims from the
