### Live-check discovery (R5, found during R4)

With a key, the real SAM 3.1 API returns HTTP 200 whose full output
arrives in a single `response.output_text.done` event — there are **no**
`response.output_text.delta` events. `worker/src/meta.ts` collects only
deltas, so every real SAM response reads as empty text and the grounded
path silently degrades to box-only: the W3-05 live acceptance could
never pass in production despite the (correct) mocked suite. Real wire
output captured 2026-11-01 (synthetic red-rectangle photo, phrase
"red rectangle"): `<0f>0<|box;x1=300;y1=300;x2=419;y2=1098;w=720;h=1280;
c=0.9298…|><|mask;x=0;y=0;c=0.9298…;data=799,120,…|>` in ~0.6 s — the
§7.3 shape, confirming the parser work in review 0002 R1 against the
real grammar.

## Findings

### W2-07 — `.echo` file fallback (BLOCK)

- **B1 (BLOCK)** Imported `routeId`/asset ids are interpolated into
  storage paths unsanitised: a crafted `.echo` writes attacker bytes
  outside `routes/<id>/` (traversal via `../`, ids containing `.`).
- **M1 (MAJOR)** No size cap anywhere: picker `readBytes()` loads the
  whole file, then codec + base64 decode multiply it — OOM, uncatchable
  by the VM's `catch (Exception)`.
- **M2 (MAJOR)** Expiry not enforced on file import (`open` without
  `nowMs`), though the sheet displays expiry while Save stays available.
- **M3 (MAJOR)** Duplicate import silently overwrites a route and leaves
  stale assets from the previous version behind.
- **M4 (MAJOR)** Plaintext export in `exports/` is never cleaned up —
  an unbounded-lifetime unencrypted duplicate, name-colliding across
  same-named routes.
- **M5 (MAJOR)** Picker read failure throws inside the ActivityResult
  callback — crashes/leaks instead of surfacing the VM error state.
- Verified good: the S-scoped core is right — warning-before-write with
  no bypass (only `confirmFileShare` writes, guarded; gate tested),
  inline warning panel (no dialog), minimal FileProvider (`exports/`
  only, not exported), typed malformed-content errors, preview-before-
  save, real-codec round-trip.

### W4-03 — Robustness (BLOCK)

- **B1 (BLOCK)** `RecoveryAdvisor` is dead code: nothing consumes
  `listRecoverable`/`resumeRoute`; recovery is never surfaced.
- **B2 (BLOCK)** Advisor returns string routes (`"record?resume=…"`)
  incompatible with the typed `EchoRoute` graph — unusable even wired.
- **B3 (BLOCK)** Capture-only drafts on Home open Review, which reports
  the draft route missing — a dead end for the exact kill-mid-record case.
- **B4 (BLOCK)** No test/evidence for permission wiring or the abuse pass.
- **M1 (MAJOR)** Returning from system Settings doesn't refresh status
  (`LaunchedEffect(Unit)`, no resume observer).
- **M2 (MAJOR)** Camera bind failure still crashes (unguarded
  `ensureBound`), and `RecordViewModel` swallows start failures —
  `error` never populated.
- **M3 (MAJOR)** Record ViewModel is `remember`-scoped; process death
  loses the session, and nothing reloads the autosaved log into one.
- **M4 (MAJOR)** Autosave writes are non-atomic; a kill mid-write
  truncates `capture.json`, and the advisor then silently drops the draft.
- **M5 (MAJOR)** First launch is mislabeled DENIED ("Camera was denied").
- Verified good: inline gate panel (no raw dialogs), fail-closed
  request-before-use, W1-03 Record behaviour preserved, minimal manifest
  (portrait lock only), advisor logic itself correct and tested.

### W5-02 — Camera overlay (BLOCK as Complete; not merged by decision)

- **B1** No projection and no landmark anchoring exists (the code says
