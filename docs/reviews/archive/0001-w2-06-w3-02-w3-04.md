## Findings

### W2-06 — Navigation screens and haptics (BLOCK)

- **B1 (BLOCK)** `NavigateScreen` creates the ViewModel with `remember`, so
  `onCleared()` never runs: motion collectors leak past the screen and a dead
  ViewModel can still fire haptics / `onArrived` from other destinations.
- **M1 (MAJOR)** The ARRIVED test asserts unordered `contains` of two haptic
  patterns — not the sequence the acceptance criterion names.
- **M2 (MAJOR)** Arrived summary claims `${landmarks.size} landmarks
  confirmed`; that is the route total, not confirmations from this walk.
- **M3 (MAJOR)** No ViewModel-level coverage beyond ARRIVED/UNCERTAIN, and
  the §8.4 waveform timings are untestable (`private`). Waveforms verified
  verbatim against §8.4 by inspection.
- Verified good: phase mapping is structural (UI state *is* `NavUi`), haptics
  fire on `NavEvent` transitions only, no HTTP in `nav/`, `NavigatorTest`
  extraction to `TestLogs.kt` weakened no assertion, Arrived writes nothing.

### W3-02 — Consent, API client, Processing screen (BLOCK)

- **B1 (BLOCK)** On `main` the worker jobs API the client calls does not
  exist (it arrives with the unmerged W3-04 branch, which carries the frozen
  W3-03 contract). Resolved by R4's merge, not by client code.
- **B2 (BLOCK)** Consent is a UI convention: `send()` does not require the
  Consent phase, hard-codes the consent flag at upload time, and `retry()`
  re-uploads under a new job with no consent shown. The upload guard is also
  racy (double-tap submits twice).
- **B3 (BLOCK)** The consent copy promises "delete now, from this screen",
  but `hasJob` is never `true`, so the button never renders; re-entering
  with an errored job orphans it server-side; `deleteNow()` reports success
  even when the server delete fails.
- **M1 (MAJOR)** Same `remember` ViewModel leak as W2-06 B1; Cancel only
  pops the back stack while polling continues, and `EchoApiClient` swallows
  `CancellationException` as a network error.
- **M2 (MAJOR)** No HTTPS enforcement on a bearer-token photo upload.
- **M3 (MAJOR)** One transient poll error collapses to `Failed`, whose only
  recovery was the destructive re-upload in B2.
- Verified good: single upload path (only `send()` submits), fail-closed on
  blank config / empty file set, contract mapping matches the frozen W3-03
  schemas exactly, no token logging, raw route geometry never leaves.

### W3-04 — Workers AI scout chain (BLOCK)

- **B1 (BLOCK)** A wrong-`nodeId` answer throws *outside* the per-model
  loop, so Gemma never runs for exactly the invalid-output class the
  fallback exists for.
- **B2 (BLOCK)** Candidates are cleaned against manifest refs, not the
  images actually loaded from R2 and sent — a candidate can be boxed on a
  photo the model never saw.
- **B3 (BLOCK)** No test proves invalid-Llama → Gemma-succeeds (including
  the B1 class); the mocked suite proves only happy path + all-fail.
- **M1 (MAJOR)** The no-`response_format` retry regex matches any error
  containing "format"/"schema", including Zod parse failures — spec allows
  that retry only when the model rejects `response_format`.
- **M2 (MAJOR)** No per-model timeout, and deterministic scout failures are
  retried 4× by the Workflow step instead of failing non-retryably.
- **M3 (MAJOR, deferred by plan)** Pipeline discards the scout result
  (`models: "none"`, empty candidates in the public result). Plan assigns
  assemble content to W3-06 — recorded here so it is not lost; not fixed.
- Verified good: model ids/routing order and §7.1 system prompt verbatim,
  never-free-text on the main path, no W3-03 contract regression (jobs.ts /
  types.ts byte-identical to the frozen slice), no secrets in the diff.

## Fix slices

### R1 — W3-04 scout fallback and image filtering (worker)

Move `nodeId` validation inside the per-model attempt so any invalid model
output (schema-invalid, wrong checkpoint) falls through to the next model;
clean candidates against the ids of images actually loaded and sent; only
retry without `response_format` when the binding call itself rejects it;
bound each model call with a timeout and make deterministic scout failures
non-retryable at the Workflow step. Tests: invalid-Llama → Gemma-succeeds
(schema-invalid and wrong-`nodeId`), candidate referencing an unloaded
image is dropped, existing suite stays green.
Gate: `cd worker && npm run typecheck && npm test`.

### R2 — W2-06 navigation lifecycle and proof (shared)

Scope `NavigateViewModel` to the navigation back-stack entry so
`onCleared()` stops motion and cancels collectors; assert the exact ordered
haptic sequence in the replay-to-ARRIVED test; Arrived summary stops
claiming confirmations it did not observe; add ViewModel coverage for one
further phase. Gate: `./gradlew :shared:testAndroidHostTest --tests
"app.simt.echo.ui.screens.navigate.NavigateViewModelTest"` plus the iOS /
assemble gates the original slice recorded.

### R3 — W3-02 consent gate and polling honesty (shared)

`send()` uploads only from the Consent phase, claimed atomically so a
double-tap cannot submit twice; `retry()` deletes the dead job and returns
to Consent instead of re-uploading; an existing job makes the promised
delete action reachable, and a failed delete keeps the record and says so;
`ProcessingViewModel` gets back-stack scoping like R2, the client rethrows
`CancellationException`, requires HTTPS (loopback excepted for local dev),
and polling tolerates transient failures before declaring `Failed`. Tests
for: no submit before consent, no submit from a non-Consent phase,
retry-shows-consent, delete-failure honesty, transient-poll recovery.
Gate: `./gradlew :shared:testAndroidHostTest --tests
"app.simt.echo.ui.screens.processing.ProcessingViewModelTest" --tests
"app.simt.echo.transfer.EchoApiClientTest"` plus iOS / assemble gates.
