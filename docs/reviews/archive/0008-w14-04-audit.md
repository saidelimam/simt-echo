## 1. Fingerprints + magnetic profiles — APPROVE

- Substrate (`RoutePerception`: `fingerprints`, `waypointPrints`,
  `magProfile`, `sigilSeed`, `health`) rides **inside the bundle body
  only** (`model/RoutePerception.kt:56-63`). It never enters an HTTP
  payload: `grep` for `perception|fingerprint|magProfile|waypointPrint`
  over `transfer/`, `worker/src/types.ts`, `jobs.ts`, `uploads.ts`
  returns only the disclosure constant, the QR `s=` fingerprint line,
  and KDoc — the upload manifest (`media/ManifestBuilder.kt:103-111`)
  carries geometry + per-frame flags + a one-line route-context string,
  never embeddings or mag samples.
- Bundle-only means inherited bundle controls apply: sealed `ECX1`
  AES-256-GCM containers (`bundle/BundleCodec.kt:58-64`),
  receiver-side expiry at open (`BundleCodec.kt:82-87`), producer size
  gate 64 KB (`RoutePerception.kt:74-89`, enforced by `encode` at
  `BundleCodec.kt:48-50`), and export-preview disclosure
  (`PERCEPTION_DISCLOSURE`, `transfer/ExportSelection.kt:48-49`,
  surfaced via `ExportSummary.hasPerception` at
  `ExportSelection.kt:174-209`).
- Mag capture stores orientation-invariant scalars only (|B| magnitude +
  gravity-aligned vertical, `capture/MagProfiler.kt:27-41`); no raw axis
  data is ever stored, and zero-mean normalisation at match time cancels
  hard-iron offsets (phone-independence claim, `MagProfiler.kt:12-18`).
- Place-derived quantization is µT×10 int16 (`MagProfiler.kt:138-148`);
  embeddings are int8[256] (`RoutePerception.kt:110-116`).

## 2. Ready-on-arrival consent ordering — APPROVE

- Load-bearing order consent → metered gate → privacy filter → network
  is enforced in the code path (`transfer/ReadyUpload.kt:103-126`) and
  pinned by `ReadyUploadTest`. Default off
  (`ReadyUploadConsent(enabled = false)`, `ReadyUpload.kt:16-19`); no
  call reaches the API without consent or on a metered network under
  Wi-Fi-only consent. `finish` fails closed without consent or staged
  windows (`ReadyUpload.kt:133-140`); `discard` deletes staged uploads
  server-side and keeps the record on failure so orphans fall to the
  server TTL sweep (`ReadyUpload.kt:142-161`).

## 3. Staged-upload expiry — APPROVE

- 1 h staging TTL (`worker/src/uploads.ts:17`), enforced lazily on every
  read (`loadUploadMeta`, `uploads.ts:72-84` — expired reads sweep their
  own area and answer 410) plus an opportunistic cross-upload sweep on
  create (`uploads.ts:300-304`) and the exported
  `sweepExpiredUploads` (`uploads.ts:112-146`, orphans included).
- Job create consumes staging (`uploads.ts:186-189,265-268`):
  single-use sessions cannot seed a second job. Proven by
  `uploads.test.ts:165-191` and `jobs.test.ts:797-828` (backdated
  `createdAt` → 410 `upload_expired` on every endpoint + sweep).
- Worker suite green: 141/141 (`npm test`, §9).

## 4. SAM cache scoping + deletion — APPROVE

- Cache key = sha256(media) + phrase + model + params, stored per job
  (`jobs/<jobId>/sam/cache/<key>.txt`, `worker/src/samLens.ts:164-217`).
  Cross-job reuse exists only via the sanctioned `resumeOf` path
  (`samLens.ts:201-208`, budget file contract in
  `uploads.ts:243-255`), adopted into the new job's own prefix.
- Job DELETE sweeps the whole `jobs/<id>/` prefix
  (`worker/src/jobs.ts:224-233`) — cache, events, inputs, evidence —
  proven by `jobs.test.ts:371-383` (`media.store.size` is 0 after
  DELETE); unknown ids answer idempotent 204.
- Pre-filter runs before any SAM spend: candidates failing the W11-04
  frame flags drop to box-only with zero frames
  (`samLens.ts:259-268,368`), and the governor reserves estimates
  synchronously before any call (`samLens.ts:125-140`).

## 5. Face pre-filter efficacy — APPROVE (with residual R3, fixed F3)

- Where a detector is present the chain is fail-closed end to end:
  UNKNOWN maps exclude-safe (`capture/FacePrivacy.kt:56-57,83-84`);
  keyframe bytes flagged `faceFree == false` are withheld from the
  upload while the flag still rides the manifest so the worker drops
  the box (`ProcessingViewModel.kt:772-781`,
  `ManifestBuilder.kt:270-280`); `ReadyUpload` excludes pre-network
  (`ReadyUpload.kt:109`).
- **F3 (High, fixed in this slice): the consent copy promised the
  filter unconditionally** (`consentCopy` appended
  `FACE_FILTER_DISCLOSURE` always) while production wires **no**
  detector (`faceDetector = null` default,
  `ProcessingViewModel.kt:140`; Android binding returns the
  must-not-wire NoOp, `androidMain/.../AndroidFaceDetector.kt:22`).
  The copy now renders the sentence only when a detector is active
  (`ConsentInfo.faceFilterActive`, `ProcessingViewModel.kt:67-80,95-103`,
  wired at `ProcessingViewModel.kt:214`), pinned by
  `consentCopyOmitsTheFaceFilterWhenNoDetectorIsWired`
  (`FacePrivacyTest.kt:104-112`).
- Residual R3: cut video **clips** are never face-scanned (no frame seam
  in the Media3 cut path, no ML Kit face dep in the catalog) — owed,
  recorded at `FacePrivacy.kt:29-33` and
  `ProcessingViewModel.kt:133-138`. Keyframe withholding + worker
  box-drop hold regardless.

## 6. Live Update lock-screen contents — APPROVE

- Points carry landmark **titles only** — never a photo, crop, or asset
  id (`platform/LiveUpdate.kt:21-22,59-68`); the Android sink posts
  title + text + progress segments/points with no image APIs
  (`androidMain/.../LiveUpdate.android.kt:29-66`). Verified by reading
  both files: no `setLargeIcon`/`BigPictureStyle`/image load exists on
  the path. `POST_NOTIFICATIONS` is primed in context, never at launch,
  and refusal degrades to no notification
  (`LiveUpdate.kt:223-248`, sink guard at `LiveUpdate.android.kt:30-37`).

## 7. F1 — LAN token CSPRNG (High, fixed in this slice)

- Before: `randomBytes` defaulted to `Random.nextBytes`
  (`TransferService.kt:40`, old). Bounded (the token is a LAN bearer
  only; decryption still needs the QR key), but a seeded PRNG for a
  bearer credential is a High by the severity scale above.
- After: `expect fun secureRandomBytes`
  (`transfer/SecureRandom.kt`) with platform actuals — `SecureRandom`
  on Android/JVM (`SecureRandom.android.kt`), `SecRandomCopyBytes` on
  iOS (`SecureRandom.ios.kt`) — and the service default is now
  `::secureRandomBytes` (`TransferService.kt:40`). The injectable
  lambda stays for deterministic tests.
- Pinned by `SecureRandomTest` (size/empty/uniqueness ×64 plus
  `defaultOfferTokensAreUnique` end-to-end through `offer`).

## 8. F2 — Purge on resume (Medium, fixed in this slice)

- Before: `purgeExpired` ran at process start only
  (`EchoApplication.kt:26-33`, old) — a long-running app kept an
  expired route visible until restart (share/export stayed
  fail-closed).
- After: `AppGraph.purgeExpiredRoutes(nowMs)`
  (`AppGraph.kt:50-59`) is called from `onCreate` **and** from
  `MainActivity.onResume` (`MainActivity.kt:37-45`), so a route that
  expires in the background is gone before its row can render.
- Pinned by `ExpiryPurgeResumeTest` (expired/live/no-expiry routes
  through the exact resume entry point).

## Residual risks (none blocking)

- **R1 — QR key is cleartext by design** (inherited 0007 R2). Optical
  pairing trust model; window bounded by export expiry + start/resume
  purge (§8). No change.
- **R2 — Relay TTL + LAN-blocked transfer not device-proven**
  (inherited 0007 R4). Unit + round-trip evidence stands; device pass
  owned by the W9-04 lineage.
- **R3 — Clips never face-filtered** (§5). Owed slice needs the ML Kit
  face dep + a Media3 frame seam; keyframe withholding + worker
  box-drop hold meanwhile.
- **R4 — Plaintext `.echo` exports linger until the next share**
  (`ShareViewModel.kt:196-199` purges before writing anew). Bounded to
  app-private storage behind the file warning
  (`ShareViewModel.kt:55`); noted, not expanded — smallest diff.
- **R5 — iOS `secureRandomBytes` actual uncompiled.** The iOS target
  does not build on main (pre-existing
  `ReviewStoryUi.kt:329:35 Unresolved reference 'format'`, untouched by
  this slice); the new actual introduces no new error (it is the only
  other file in the compilation and no diagnostic names it), but it has
  not been compiled. Android/JVM actual is compiled and tested.
- **L1 — Token-value scan limitation** (inherited 0007 L1): repo
  `git grep` for key patterns is clean (§9); a random bearer has no
  matchable pattern, so the guarantee for the token is the CSPRNG
  design (§7), not the scan. No APK rebuild this audit (no release
  artefact changed).

No BLOCK findings → no slices re-opened; nothing stands between this
audit and W14-05.
