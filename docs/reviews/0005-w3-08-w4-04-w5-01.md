## Findings — W3-08 (privacy surface)

- **B1 (BLOCK)** Preview enumerates only binary assets, while the
  export carries the whole route: name, creator, timestamps, full
  geometry (nodes/legs/0.5 m path), start description, all landmark
  metadata, and `AiProvenance` (jobId + model ids + timestamps).
  Toggling a sensitive crop off nulls only the image pointer — its
  title/cue/signText still export.
- **B2 (BLOCK)** Re-export unconditionally overwrites stored expiry
  with the NONE default (defeating the sender's intent), and expired
  routes are freely exportable sender-side.
- **B3 (BLOCK)** Route delete removes only `routes/<id>/`: the
  FileProvider-exposed plaintext export survives, and the cloud job
  can be stranded (job id lived only in a nav arg / deleted draft).
- **M1 (MAJOR)** `privacyRisk` is never populated for creator-drawn
  crops or the start photo on this path — no way to flag people/plates.
- **M2 (MAJOR)** Export never re-checks `AI_SUGGESTED`: the
  never-export-unreviewed invariant is trusted, not enforced.
- **M3 (MAJOR)** Re-offer leaves the superset QR live on screen.
- **M4 (MAJOR)** Asset-less routes get no preview and no expiry control.
- Verified good: same selection applied on both export paths, risky
  shared-asset logic, import expiry (`<=`, epoch) + startup purge,
  cloud-delete error honesty, one strong round-trip asset test.
